# Part 9.2: server tool krita_paint_stroke

- **Built:**
  - **The schema** `src/krita_art_mcp/schemas/krita_paint_stroke.json`: the input as the
    contract (`layer_id` replaces `edit_id`; `brush` requires `preset_id`, `size_px` 1-1000,
    `opacity`, `flow`, `color`, `eraser`, with `preset_sha256?`, `blend_mode?` (the whitelist enum),
    `alpha_lock?`, `rotation_deg?`, `antialias?`; 1-4096 points of `x`, `y` and the seven optional
    per-point fields; `smooth`, `input_fallback`, `verify`). Output `data`: the plugin result
    without `document_id`, plus `input_applied` (`const: "flat"`); `effective_brush` has no
    `smoothing`; `antialias` is `const: true`, `protected_pixels_changed` `const: 0`, `undo_steps`
    `const: 1`, `undo_label` a non-empty string; the inline `preview` is gone. New description
    and example.
  - **`scripts/amend_schemas.py`** copies the object branch of `krita_layer_update`'s
    `data.properties.verification` into `krita_paint_stroke`'s, so the stroke's copy is never
    null and the shape has one home. It ran; `--check` is clean.
  - **`src/krita_art_mcp/strokes.py`** (pure): `path(points, smooth)` gives the bridge's
    `{start, segments}`. `none`, or fewer than three points, gives lines; `catmull_rom` gives
    exact cubics per segment p1→p2, `c1 = p1 + (p2 − p0)/6`, `c2 = p2 − (p3 − p1)/6`, end points
    repeated. One point gives `start` = that point and the zero-length line `[[x, y]]`.
  - **`src/krita_art_mcp/tools/painting.py`**: `paint_stroke` and `paint_receipt`.
    - Refusals before the journal, no operation id, in this order: `INVALID_ARGUMENT` for
      `eraser` with `alpha_lock` (details `eraser`, `alpha_lock`) and for a colour alpha other than
      1 (`alpha`, `supported: [1]`); `UNSUPPORTED_CAPABILITY` for `smooth` `basic` or
      `stabilizer` (`smooth`, `supported: ["none", "catmull_rom"]`), for `antialias: false`
      (`supported: [true]`), and for the input gate (`point`: the first index, `fields`: its
      pressure if not 1 and each per-point field present, `input_fallback: ["flat"]`), which
      `input_fallback: "flat"` alone bypasses.
    - Then `INVALID_ARGUMENT` with `details.field` (`brush.size_px`, `brush.opacity`,
      `brush.flow`, `brush.rotation_deg`, `brush.color` or `points`) for a number that is not
      finite, in the brush, the points, or the path the smoothing made. A JSON integer too large
      for a float counts as not finite (it would raise inside the smoothing).
    - The op args per the contract, defaults filled (`blend_mode` normal, `alpha_lock` false,
      `rotation_deg` 0, `preset_sha256` null, `verify` region), `color` as the bare `rgba` list,
      `accepted_points` the number of points; `journaled` with the literal
      `call.bridge.call("paint.stroke", …)` in the tool's own `send`, and
      `changes.resolve_update` making the PNGs.
    - `paint_receipt`: `from_outcome`, data the result without `document_id` plus
      `input_applied: "flat"`, text "Painted N point(s) on layer L of D; P px changed, verified
      over M."; on `Failed`, the refusal's diff inlined.
  - **`tools/changes.py`**: `_diff_image`, `_without_document` and `_document` became public
    (`diff_image`, `without_document`, `document_of`) for `painting.py`; `STEP_TOOLS` gains
    `"paint.stroke"`.
  - **Registered** in `tools.TOOLS` (17 tools) and `operations.RECEIPTS`
    (`Known("krita_paint_stroke", painting.paint_receipt, changes.resolve_update)`). Invariant 10:
    the tool is registered before the plugin op exists on this branch, which is right only
    because integration merges part 9.1 before any release.
  - **Instructions:** a bullet after `krita_layer_update`'s: one stroke per call, one undo step,
    checked like a layer change and undone on a leak; per-point pressure, tilt or timing is
    refused unless `input_fallback` is flat, which paints every point at pressure 1. The last
    line: the owner may be watching Krita, and must not edit brush presets while you paint. "No
    tool writes raw pixels or runs code" stays. Nothing else trimmed.
  - **Tests:** `tests/test_strokes.py` (the arithmetic exact on multiples of 6, the shared tangent
    at inner points, lines, two points, one point); `tests/test_paint_tool.py` (each refusal with
    `operation_id` null, no journal line and no bridge call; the non-finite refusals called on
    the tool directly, since the MCP client turns NaN into null and the schema then refuses it;
    the defaults and given values in the op args; `paint_receipt` and `resolve_update` on
    hand-built `Done` and `Failed` outcomes, each receipt validated against the output schema);
    `tests/test_tools.py` lists 17 tools; `tests/test_envelope.py` holds the stroke's blend enum
    to `observe.BLEND_MODES`, its `verify` enum to `bridge_core.verification.MODES` and
    `points.maxItems` to `observe.LIMITS["stroke_points"]`; `tests/test_schemas.py` holds the
    stroke's verification equal to `layer_update`'s object branch, and its drift test clears both
    of the stroke's copies.
- **Measured** (this checkout, `mcp` 2.3.0, `jsonschema` 4.26.0, `pydantic` 2.14.1, no Krita):
  - **NaN and Infinity reach a tool:** the server's JSON-RPC parsing accepts the `NaN`,
    `Infinity` and `1e400` tokens as floats, and jsonschema's `minimum` and `maximum` let NaN
    through. Hence the finiteness refusal.
  - **The op args are not in the journal:** its dispatched line holds the agent's arguments, so
    the tests read the op args by wrapping `BridgeClient.call`, and read the journal for the
    dispatched line and its arguments.
  - **A valid call on this branch** reaches the bridge, which answers `INVALID_ARGUMENT`
    "Unknown op 'paint.stroke'.", as expected before part 9.1.

- **For the shared documents:**
  - **CHANGELOG:** "`krita_paint_stroke` paints one native brush stroke on a paint layer, one
    undo step, verified against protection and undone on a leak; `smooth: catmull_rom` curves the
    path on the server; per-point input is refused unless `input_fallback: "flat"`." And: "The
    server instructions cover painting strokes and ask the owner not to edit brush presets while
    an agent paints."
  - **README tool line:** "`krita_paint_stroke`: one native brush stroke with a Krita preset on a
    paint layer, verified over its reach (or the whole canvas) and undone on a leak."
  - **Deliberate decisions for the done-note:** the refusal order (argument errors before
    capability gaps); the finiteness refusal before the journal (not in the contract's list, but
    the plugin's args must be finite and a huge integer would otherwise raise inside the
    smoothing); `undo_label` typed as a non-empty string rather than a constant, so another
    Krita build's label is reported, not turned into `INTERNAL_ERROR`; `effective_brush.blend_mode`
    a string, as the contract gives it, not the whitelist enum; the three `changes.py` helpers
    made public.
  - **Backlog:** a `number` input lets NaN through its schema's `minimum` and `maximum`
    (`integer` inputs refuse it), so other tools' number inputs, such as `layer_update`'s
    `opacity`, reach the plugin with NaN; only `krita_paint_stroke` refuses it on the server.
