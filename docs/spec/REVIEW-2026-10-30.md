### Medium

**F1. `serve` has no stale-plugin gate, so a forgotten restart fails as the agent's own mistake.**
*(second read)* `bridge_client._open` reads `pid`, `protocol`, `port`, `token`, `session_id` and
`ephemeral_reads` from `bridge.json` (`bridge_client.py:263-279`) and nothing else; the
`plugin_version` and `plugin_hash` the plugin publishes there (`bridge.py:93-110`) are read by
`probe` and `doctor` alone (`setup_checks.py:77-84`), which is how invariant 11 is scoped. Every
tool session has added ops under protocol 1 (`preview.read` in 0.11.0, `document.save` and
`document.save_finish` in 0.12.0), so a plugin one release behind answers each new tool with
`INVALID_ARGUMENT "Unknown op …"` (`jobs.py:156-159`), which reads as a bad call rather than a
setup step. The handoff carries "every plugin change needs `install-plugin` and a Krita restart"
as a standing trap because it has already bitten. *Cost:* the H3 check and the H1 trial run
`serve` without the probe in front of it. *Remedy:* `_open` refuses a `plugin_version` other than
the server's with `PROTOCOL_MISMATCH` and `setup_checks.INSTALL` as the fix (one check, one test).

**F2. The wait-before-read scan names `pixelData` only; a projection read without a wait would
pass it.** *(second read)* `tests/plugin/test_source_scans.py:222-228` matches calls named
`pixelData` and `waitForDone`; `krita_adapter/documents.py:368` reads `projectionPixelData` (it
waits at `:365`, so the code holds). Invariant 6's stated enforcement does not cover the second
read Krita offers, nor `pixelDataAtTime` when Phase 5 arrives. *Remedy:* scan every name that
ends in `PixelData` (or list the three); falsify once.

**F3. `krita_document_inspect` writes the whole selection to a transfer file to count two
numbers.** `bridge_core/inspection.py:119-130` reads the selection's pixels over its bounds and
writes them as an `A8` file on every inspect with a selection; `tools/documents.py:164-186` reads
the file, counts the non-zero bytes, sums them, and deletes it. An 8192 × 8192 master with a
canvas-wide selection is a 64 MB file written and read per inspect, and inspect is the call an
agent makes most. The plugin counts the same bytes itself for `selection.set`
(`selections.py:101`). *Remedy:* count `selected_pixels` and `coverage_px` in the plugin, as
`selection.set` does, and send the numbers; `krita_capture` with `target: selection` already
gives the pixels to anyone who wants them.

**F4. A document larger than 8192 × 8192 can be opened, painted and previewed, but never
saved.** *(both)* `bridge_core/saving.py:281-287` refuses the save (`UNSUPPORTED_CAPABILITY`),
because the verification reads the live composite, the reopened composite and every live and
reopened node over its bounds, and the server decodes the whole `mergedimage.png`, all unbanded
(`saving.py:101, 111-114, 301-319`, `imaging.py:230-252`). Open has no bound since the baseline
became lazy, captures tile, strokes verify a region, previews crop. The bound is right for the
reads as written (review 10 F13 named the same ceiling for Phase 2's whole-canvas operations),
but the instructions do not say it, and an agent learns it only when its work cannot be kept.
*Remedy:* for round 1, name the bound in the instructions (session 14) and the user guide (15);
for Phase 2, band the save's reads and hashes, as `verification.check` already bands its compares.

### 8.8 Architectural decisions to revisit

1. **The protocol number is the only compatibility signal `serve` reads, and it never moves**
   (F1, F10): ops and a field were added under protocol 1 for six releases; the plugin hash
   stands in for it in `probe` and `doctor` but not in `serve`. Either bump the number whenever
   the op set changes, or let `serve` refuse a plugin whose version differs from the server's.
2. **`baseline_untouched` by hashing the source on every save and close** (F9): the stat check
   the finish uses is enough, with a hash only when the stat moved.
3. **The selection crossing as a file for two counts** (F3): count in the plugin.
4. **Whole-canvas reads bounded by budgets rather than banded, in the save and the fingerprint**
   (F4, F8): the 8192 × 8192 cap is the first hard limit an owner with a larger master meets, and
   Phase 2's whole-canvas filters meet the same wall (review 10 F13). Banding is Phase 2's; the
   instruction is round 1's.
5. **Measurement ops in the product** (F6, F27, F31): `probe.*` and half of `harness.*` exist to
   answer questions in done-notes, and every user's plugin ships them. One closed namespace,
   documented, with what gates kept and the rest retired, or a harness-only extension.
6. **Argument validation written twice by hand** (F19): Phase 2 adds about nineteen tools. Either
   the plugin keeps its own checks and each pair gets a parity test, or the server becomes the
   one validator of argument shape and the plugin checks only what Krita's state decides.
7. **Schemas that advertise what Phase 1 refuses, and outputs that carry placeholders** (F23):
   the contract's shape against an agent's first attempts; the Phase 2 intake decides for the
   schemas it amends, and ARCHITECTURE lists which placeholders become live when.
8. **Three verified-mutation ladders, and the save's** (review 10 F3): one frame before Phase 2's
   first mutating op; unchanged, still the Phase 2 intake's first item.
9. **The journal as permanent, unbounded files** (`journal.py:19`, PDD Part 6): 44 MB a heavy
   week, read in full by the first lookup of each server process (3 ms today); fine for round 1,
   a retention rule before a painting year.
10. **The server-wide `CALLS` lock** (`tools/__init__.py:64, 104`): one process serialises every
    tool call, so a client cannot inspect while its own 45-second save runs. Right today (one
    agent, sequential calls); worth a sentence in ARCHITECTURE and a revisit when a client runs
    tools in parallel.
11. **The probe's timings depend on the Krita it runs on** (F34): ARCHITECTURE's baseline should
    name the condition (an empty Krita) its numbers were taken under, or the probe should record
    the open-document count beside its times.
