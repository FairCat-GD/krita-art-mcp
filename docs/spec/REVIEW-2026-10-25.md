# Review 10: the architecture after the paint-safely milestone

Session 10 of round 1 (SPEC decision 2), 2026-10-25. The code and tests of sessions 1–9 were
read cold against `SPEC.md` (whole), with `PDD.md` Parts 4 and 8 — Part 4's Phase 2 and Phase 3
sections included — and `REVIEW-2026-10-24.md` beside them. This file is evidence, not scope: it
changes no product code and cuts no version. The owner chose, in plan mode, which findings become
scope; §6 says where each landed.

**Method.** Every product file was read in full: the plugin core (34 modules), the adapter
(10 modules), the server (25 modules and the 8 probe modules), the three scripts, and every test
(686 test functions across 30 files). Each file was read against the boundary rules of SPEC §3,
the invariant it serves in §5, and what sessions 11–12 and Phases 2–3 will put through it, with
block 10's focus first: protection, the verification core, rollback, the undo ledger and the
reach analysis. A second, independent cold read of the paint core was run without sight of the
first read's notes; its findings were verified on the code path before they were kept (it added
F1, F2, F6 and F8, sharpened F4 and F5, and confirmed the floor arithmetic and the retry safety;
three others duplicated the first read's). Then `verify`, `probe` and `doctor` were run and the
data directory listed before and after. Every claim below points at `file:line` on commit
`dffdf73` or at a measurement.

**Severity.** *High*: an invariant is weakened, or a planned session is blocked as written.
*Medium*: a defect or debt that will cost a later session. *Low*: drift or untidiness. *Info*:
recorded, no remedy.

### 2.3 The undo ledger and the protection floor

No sequence was found that crosses the floor. `protection.set` seals (`protection.py:113`);
`undo_available = applied − max(floor, bottom)` (`ledger.py:76-77`); `push` zeroes the redo
allowance and deletes the redo tail (`ledger.py:50-56`); a rollback's `rolled_back()` adds no
redo (`:58-62`); K43's redo of a rolled-back stroke is therefore unreachable, and the probe holds
it live. Krita dropping steps off the bottom of its stack only shrinks what the ledger offers
(`bottom` only grows), and a mismatch degrades to FOREIGN, which seals. The witness (the target's
bytes over the step's diff, hashed on both sides of it, `ledger.py:12-35`, checked in
`history._shows`/`_holds`) tells apart steps that share a label and node state; the probe's
witness check undoes a stroke by hand under another of the same label and watches history stop.

## 3. Findings

### High

None.

### Medium

**F1. A `BaseException` mid-`layer.update` leaves an unverified change with no rollback, no
unsafe mark and no seal.** `update()` catches only `BridgeError` and `Exception` around the
mutation (`bridge_core/layer_update.py:89-95`); an interrupt during `port.set_properties`
(`:74`) escapes to `jobs._run`, which anticipates interrupts (`jobs.py:201-210`) and fails the
op — but the half-applied change is never verified, rolled back or marked, and `_blend`'s own
guard seals without marking unsafe (`layer_update.py:133-136`). The stroke closes exactly this
window (`painting.py:141-145`). The tests parametrise `raised: BaseException` but raise only
`Exception` subclasses (`tests/plugin/test_layer_update.py:412-434`). Invariant 5 is weakened in
that window. *Remedy:* mirror the stroke's `BaseException` handler (seal, unsafe, re-raise), and
falsify it with a non-`Exception` raise.

**F2. `history.step` has two unguarded windows after a mutation.** (a) `step_history` calls
`move` bare (`history.py:149-163`): a raise between `_act` and its confirmation — the witness
read can raise `LAYER_NOT_FOUND` (`history.py:71-79`, `krita_adapter/documents.py:415-422`) —
leaves Krita one step moved, the ledger not advanced and the document dirty but not unsafe. The
stroke's and `layer_update`'s rollbacks wrap `move` in a try that converts any raise into unsafe
(`painting.py:287-325`, `layer_update.py:186-213`); history does not. Later calls degrade to
FOREIGN and seal, so it fails safe-ish, but invariant 5's letter does not hold on that path.
(b) The region capture calls `transfer.write` directly (`history.py:164-171`): an `IO_ERROR`
there fails the whole op, journalling a failure receipt for undos that actually ran — the record
is wrong, though nothing repeats (the error is non-retryable). `verification.files` already has
the right pattern: best-effort, a file that cannot be written is left out
(`verification.py:398-431`). *Remedy:* wrap each `move` in `step_history` (an escape marks the
document unsafe), and make the capture best-effort.

**F3. The verified-mutation skeleton has three hand-rolled homes that have already drifted.**
`painting.painted`/`roll_back`/`restore` (`painting.py:147-353`),
`layer_update.update`/`_roll_back`/`_restore` (`layer_update.py:38-213`) and
`layers.create`/`_roll_back` (`layers.py:527-573`) implement invariant 5's sequence —
before-read, mutate, after-read, verdict, rollback, confirm or unsafe — three times with
diverging details; F1 and F2 are drift between the copies. Phase 2's filters, transforms and
fills "under the same rules" (PDD Part 4) would each be another copy, and `Step`'s single-layer
witness (`ledger.py:12-13`) would not carry a multi-layer operation. *Remedy:* before Phase 2's
first mutating op, extract one guarded-mutation frame in `bridge_core` and make the stroke,
`layer_update` and history its clients; the Phase 2 intake owns it. Round 1 only closes F1 and
F2 in place.

**F4. Region scope's last line of defence is the margin model, which rests on two unmeasured
Krita facts.** In region mode the composite is read over R and the target over the ring R′ only
(`painting.py:96-123`); a change beyond R′ that falls inside the target's old bounds is read
nowhere, and the bounds check sees only growth past `old ∪ R′` (`painting.py:653-663`).
Soundness therefore rests on (a) the pixel engine displacing dabs by scatter alone, and (b) an
image tip fitting a size × size square (`brushes.py:9-11`, `EXTENT[IMAGE] = √2⁄2`) — held today
by the fail-closed parse, by about 50 stock presets measured in session 9, and by the ring, which
caught one real scatter underestimate there. A predefined tip taller than the brush size would
break assumption (b). *Remedy:* record both as measured assumptions (here and in
`ARCHITECTURE.md` at session 15), and measure a deliberately tall image tip live against the
extent bound.

### Low

**F5. Unpinned duplicates — the F26 pattern recurring in session 9's code.**
(a) `bridge_core/painting.py:36-37` (`MAX_POINTS`, `MIN_SIZE_PX`, `MAX_SIZE_PX`) against
`krita_paint_stroke.json` (maxItems 4096, size 1–1000) and `observe.LIMITS["stroke_points"]`,
which the schema is pinned to while the plugin copy is not; (b) a third `SRGB_PROFILE` in
`krita_adapter/painting.py:12`, though the adapter already imports from `bridge_core`;
(c) `probe/painting.py:27` `LABEL` against `history.LABELS["paint.stroke"]`; (d) the
allowed-mask/canvas-size rule and message in two places (`verification.py:222-225`,
`protection.py:96-99`); (e) `_refuse_reach` near-verbatim in `painting.py:567-575` and
`layer_update.py:301-309`. *Remedy:* parity tests for (a)–(c); one home for (d) and (e).

**F6. A `history.step` that hits LOST mid-batch returns a receipt that does not say the document
is now unsafe.** `stopped: "unconfirmed"` covers both the recoverable REVERSED and LOST
(`history.py:157-162`); `move` set unsafe, so the next call answers `DOCUMENT_UNSAFE`, but the
receipt under-reports. *Remedy:* distinguish LOST in `stopped` (a small schema enum addition).

**F7. The probe's harness KRA export never retries `BUSY`.** `probe/opening.py:100-126` reports
the autosave flake as a FAIL; the handoff carries "a rerun passes" as a standing trap instead.
*Remedy:* one retry with a fresh request id.

**F8. A replayed receipt loses the inline diff image.** `stored()` keeps one text line and the
structured content (`tools/dispatch.py:55-57`), so a retried failed stroke replays without the
`ImageContent` diff the first call carried (`tools/painting.py:156-161`); the artifact path and
counts survive. Cosmetic.

**F9. The assumed undo-stack default is unmeasured.** `krita_adapter/documents.py:264-271`
falls back to 30 when `undoStackLimit` is unreadable; a larger real default only makes the
ledger's `bottom` over-grow, which over-refuses deep undos (conservative, never unsafe).
*Remedy:* measure Krita's default live and record it.

### Info

**F10.** The undo labels are Krita-5.3.4-English literals (`history.py:20-27`, as its comment
says). On a non-English Krita every rollback becomes `ROLLBACK_FAILED` and every history step
FOREIGN — fail-safe but unusable. In scope for round 1 (the owner's machine); already in
`docs/BACKLOG.md` (*Undo labels in other languages*, 0.7.0), so nothing to add.

**F11.** The benchmarks run without an active selection; each stroke's ledger fingerprint reads
the global selection over its bounds (`ledger.selection_state`), so a canvas-wide selection on an
8k master adds a ~64 MB read per stroke that no benchmark sees. Recorded; the headroom (§7)
leaves room.

**F12.** The reach analysis refuses a filter layer inside a non-pass-through group above the
target (`verification.py:149-155`), though such a layer cannot see below its own group.
Conservative over-refusal; safe. Recorded.

**F13.** Bounded growths, measured and accepted: the bridge's non-ephemeral dedup state grows
for the Krita session (invariant 9's amendment; 1,216 operations after this run's N-01, §7);
history's region capture and the failure diff are canvas-bounded rather than
`MAX_READ_PIXELS`-capped. Phase 2 whole-canvas operations will need banded *reads*, not just the
banded compares `verification.check` already does. Recorded.

## 5. The paint core against sessions 11–12 and Phases 2–3

- **Session 11 (preview_render).** Reads only: baselines (`baselines.load` memory-maps the
  `.npy`), captures through the transfer path, Pillow composition. The lazy `as_opened` baseline
  (block 11's F10 amendment) means `opening._open` stops writing the baseline eagerly and the
  first render that needs it asks for it; the resolver pattern (files named by operation id,
  found before made) is ready for it. Nothing in the paint core is in its way.
- **Session 12 (document_save).** `export_kra` exists for the harness
  (`krita_adapter/documents.py:349-358`, batch mode, never `saveAs`); the save tool adds the
  verify-by-reopen. The settled close (`closing.py`) and the lease cover the reopen-and-close
  inside verification. H4's long save will exercise F24's bounded grace — the case the 6a remedy
  was reshaped for.
- **Phase 2 (construct).** `Registry.guarded` remains the seat for `permitted_operations`; the
  reach analysis, `verification.read`/`check`/`files` and the ledger generalise; the
  orchestration does not (F3), and multi-step operations (one or more undo steps per op) need
  the frame to push and confirm several `Step`s. Whole-canvas filters on large documents meet
  F13's read bound.
- **Phase 3 (integrity).** The envelope's `revision: null`, `expected_revision` rejected as
  unknown, `ledger.fingerprint` (node states + selection hash) and `Step`'s
  before/after fingerprints are the start of the state fingerprint; `guarded` is where
  `expected_revision` checks land. The journal's attempt/outcome model already distinguishes
  uncertain from unregistered, which `edit_rollback`'s recovery will lean on.
